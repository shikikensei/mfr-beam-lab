# 作者に聞かずに決めたこと

作者が席を外している間（2026-11-21〜）に、指示の基準に沿って決めたことの記録。
1件ごとに、何を決めたか、ほかの案、選んだ理由、あとで変えるときに触る場所。

## フェーズ4（パルスインターリーブ）

### D4-1 1つの待ちに差し込む照射は1つまで
- **ほかの案：** 待ちに入るだけ詰める／差し込まれた照射の待ちに、さらに次を入れる（連鎖）。
- **理由：** Han は「差し込む相手は直前の照射1つ」としている。入るだけ詰めると効果が大きく出て、待ちの長さという本ツールの置いた値への依存が強まる。控えめな側を選んだ。
- **変えるとき：** `src/engine/simple.ts` の `planInterleave`（`break` で1つ目で止めている）。検証は `metrics.ts` の `validate`。

### D4-2 差し込む照射は「いまの照射を始める時点で用意ができているもの」から、優先度の高い順に最初に入るもの
- **ほかの案：** 待ちの間に用意ができるものも候補にする／浮く時間が最大のものを選ぶ。
- **理由：** 土台の固定優先度と同じ物差し（優先度）で選ぶほうが、差が差し込みだけの効果として読める。浮く時間で選ぶと、優先度の低い照射が先に実行されることがある。
- **変えるとき：** 同じ `planInterleave` の候補の並べ方。

### D4-3 遠距離かどうかは目標の番号で決める（乱数を引かない）
- **ほかの案：** 乱数で決める。
- **理由：** 乱数を1回余分に引くと、ほかの方式の結果（目標の位置や機動の割り当て）が全部変わる。「属性を足す前と変わらない」をテストで保証するため。
- **変えるとき：** `src/engine/scenario.ts` の `makeScenario`（`far:` の行）。

### D4-4 待ちを持つのは追尾更新と再照射だけ。確認照射には待ちを持たせない
- **ほかの案：** 遠距離の目標の確認照射にも待ちを持たせる。
- **理由：** 確認照射は長さが一定（12 ms）で、探知直後の1回だけ。持たせても効果は小さく、説明が増える。作者の指示は「遠距離は送信 2 ms ＋ 待ち ＋ 受信 2 ms」「捜索は待ちなし」で、確認照射には触れていないので、足さない側にした。
- **変えるとき：** `src/engine/simulate.ts` の `addRequest`（`far` の条件）。

### D4-5 送信デューティ比の数え方
- **決めたこと：** 待ちのある照射は送信区間（2 ms）、それ以外は長さの半分を送信と数える。
- **ほかの案：** すべての照射で長さ全体を送信と数える。
- **理由：** エンジンは最初から、待ちのない照射を「前半が送信、後半が受信」として持っている。それに合わせた。この数え方だと、遠距離の割合を上げるとデューティ比そのものは下がる（送信 2 ms の照射が増えるため）。比べるのは、同じ状況での固定優先度とインターリーブ。
- **変えるとき：** `src/engine/metrics.ts` の `summarize`（`tx +=` の2か所）。

### D4-6 スローモーションの既定の場面では差し込みがほとんど起きないので、⑤に「差し込み」の場面を2つ足した
- **ほかの案：** インターリーブを選んだら目標数を自動で増やす。
- **理由：** 目標6の説明用シナリオでは、照射が立て込まず、差し込む相手がいない。設定を勝手に変えるより、起きる場面（目標16）へ飛ぶボタンのほうが、ほかの場面と同じ操作で済む。
- **変えるとき：** `src/main.ts` の `SCENES`。

### D4-7 2・3章の柱は、インターリーブでは 100 % を超えて積み上がる
- **ほかの案：** 100 % で切る／共有した時間を別の色で描く。
- **理由：** 「同じ時間に2つの照射が入る」ことが、柱が上限の線を越えることでそのまま見える。色を増やさずに済む。
- **変えるとき：** `src/ui/charts.ts` の `stackChart`。
